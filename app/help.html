1. Make a report

  1. Reports > New Report. Give it a code (for example INVOICE). Your applications call the report by this code.
  2. Queries (left panel): write one SELECT for each part of the document, up to 10 (Q1 to Q10). For example, Q1 is the invoice header, Q2 the invoice lines and Q3 the totals. Use your page items as bind variables: where invoice_id = :P11_INVOICE_ID. Click to check a query and read its columns.
  3. Fields: drag a field onto a band to print it, or onto a table to add a column.
  4. Toolbar (hover a button to see what it does): add text and fields (Text / Field: fixed text, {Q1.COLUMN}, or both), boxes, rounded boxes, circles, lines, images, tables and barcodes. Drag them into place, resize them by their handles, and set their properties on the right.
  5. Page: page size (A4, A3, A5, Letter, Legal, ... or a custom size), portrait or landscape, and margins.
  6. Parameters: test values for the bind variables. Then use Preview, and Save.

2. Bands

BandPrintsUse it for
Page Headerat the top of every page (or first / not first / last / not last)logo, company, document title and number
Report Headeronce, at the startbill-to and ship-to boxes, invoice details
Bodyflows over as many pages as it needstables of rows (the lines of an invoice). A table repeats its header row on every page. Whatever is below a table moves down with it.
Summaryonce, after the body (or at the bottom of the last page)totals box, amount in words, terms, signature
Page Footerat the bottom of every pagePage {PAGE} of {PAGES}, notes

A labels layout has one band, the label. It is repeated for every row of its query: across, then down. Set the label size, how many go across and down, and the gaps in Page Setup.

One document per row (Report properties): the whole layout repeats for every row of Q1. Use it for batch printing, such as all invoices of a day in one PDF. The other queries read the current row of Q1 as :Q1_INVOICE_ID, :Q1_CUSTOMER_ID, and so on. Page numbers restart for every document.

3. Tokens

TokenPrints
{Q1.CUSTOMER_NAME}a column of a query: inside a table or a label, the current row; elsewhere, the first row
{Q2.AMOUNT|FM999G999G990D00}with an Oracle format mask (numbers and dates). The Format mask property does the same for a single token.
{SUM(Q2.AMOUNT)} {COUNT(Q2)} {AVG(..)} {MIN(..)} {MAX(..)}over all the rows of a query
{WORDS(Q3.GRAND_TOTAL)}an amount in words in the Indian system (lakh, crore, paise); {WORDS(Q3.TOTAL)|INTL} uses million and billion
{PAGE} {PAGES}the page number and the page count (use them in the page header or footer)
{TODAY} {TODAY|DD/MM/YYYY} {NOW} {APP_USER} {REPORT}date, date and time, user, report name
{P11_INVOICE_ID}a parameter or page item

Print when (any element): {Q1.STATUS} = PAID prints a PAID stamp only on paid invoices, and {Q3.DISCOUNT} prints only when there is a discount. The operators are = != > < >= <=.

4. Call it from your application

One time: let your application's schema use the API

The queries of a report run as the schema that calls the API (the parsing schema of your application), so they see your own tables. Run as PDFGEN (or a DBA):

grant execute on pdfgen.pdf_api to your_schema;
-- then, as your_schema:
create synonym pdf_api for pdfgen.pdf_api;

If a call fails with ORA-06598 (insufficient INHERIT PRIVILEGES), a DBA has removed the default privilege. Restore it with grant inherit privileges on user your_schema to pdfgen;

The designer's Preview runs the queries as PDFGEN. For tables in another schema, grant PDFGEN select on them (or create views) so the preview can read them.

Get the PDF as a BLOB

declare
  l_pdf blob;
begin
  -- page items (:P11_INVOICE_ID) are read from session state
  l_pdf := pdf_api.generate('INVOICE');

  -- or give the values yourself
  l_pdf := pdf_api.generate('INVOICE', apex_t_varchar2('P11_INVOICE_ID', 1003));

  -- store it, mail it (apex_mail.add_attachment), ...
end;

Show it in the browser: a dialog, or a new tab

p_params is a list of pairs: the name of a bind variable of the report's queries, then its value. apex_t_varchar2('P11_INVOICE_ID', :P92_INVOICE_ID) fills :P11_INVOICE_ID of the report INVOICE with the value of the item P92_INVOICE_ID. A bind without a value in p_params takes the page item of that name from session state.

  1. An application process (Shared Components > Application Processes, Point Ajax Callback), named INVOICE_PDF: 
    pdf_api.download('INVOICE',
  p_params => apex_t_varchar2('P11_INVOICE_ID', :P92_INVOICE_ID));
  2. A modal dialog page (page 92 Invoice PDF) with:
    • a hidden item P92_INVOICE_ID (Session State Protection: Unrestricted);
    • a region of type URL, Inclusion Mode IFrame, URL f?p=&APP_ID.:0:&SESSION.:APPLICATION_PROCESS=INVOICE_PDF, IFrame Attributes style="width:100%;height:calc(100vh - 70px);border:0".
  3. Open the dialog from a link or a button: Target page 92, Set Items P92_INVOICE_ID = #INVOICE_ID# (a column of an interactive report) or &P11_INVOICE_ID. (an item of a form page). APEX opens it as a dialog because page 92 is a modal page.
  4. A new tab: a button, action Redirect to URL: 
    javascript:window.open('f?p=&APP_ID.:0:&SESSION.:APPLICATION_PROCESS=INVOICE_PDF:::P92_INVOICE_ID:&P11_INVOICE_ID.', '_blank');
    To download instead of showing it, add p_inline => false to pdf_api.download (in a process of its own).

Labels, batches

-- all invoices of September in one PDF (report INVOICE_BATCH repeats per row of Q1)
l_pdf := pdf_api.generate('INVOICE_BATCH',
           apex_t_varchar2('P10_DATE_FROM', '01-SEP-2026', 'P10_DATE_TO', '30-SEP-2026'));

-- labels: 24 of one product, starting on the 5th label of a sheet that is partly used
l_pdf := pdf_api.generate('PRODUCT_LABELS',
           apex_t_varchar2('P30_SKU', 'NW-GLV-100', 'P30_COPIES', 24, 'LABEL_START', 5));

5. Move reports to production

A report travels with its layout, its queries and the images it uses (logos, stamps). The target can be another schema, workspace or database.

Several reports, no designer in production: Deploy.

  1. Open Deploy, tick the reports and choose whether reports that exist in the target are replaced or left as they are.
  2. Download Script. You get one .sql file.
  3. In production, run it in SQL Developer (Run Script, F5) or SQLcl, connected as the schema that owns the PDF_ tables. It prints one line per report and commits.

Production needs only the tables and packages of 10_tables.sql to 40_pdf_api.sql: not this application.

One report, with this application on both sides: Export and Import.

  1. On Reports, the JSON link in the Export column downloads the report, images included.
  2. In the other environment, click Import on Reports. In the dialog, choose the file and, if its code is taken there, give it a new one (for example INVOICE_V2), or turn on Update the report if this code exists. Otherwise the import stops rather than overwrite anything. After the import the designer opens with the report.

Images are shared by name: importing a logo called company-logo updates it for every report that uses that name. Full steps: docs/INSTALL.md, Moving reports from development to production.

6. Good to know

  • Fonts: Helvetica, Arial, Arial Narrow, Arial Black, Times and Courier (regular, bold, italic). Arial, Arial Narrow and Arial Black are close look-alikes made from Helvetica, so no font files are needed. The rupee sign prints as Rs.
  • Characters: Page setup > Characters (language) chooses the group of characters a report prints: Western European (the default: English, French, German, Spanish, Italian ...), Central European (Croatian, Czech, Polish, Slovak, Slovenian, Hungarian, Romanian), Baltic (Estonian, Latvian, Lithuanian) or Turkish. One group per report: letters outside it are printed without their accents.
  • Images: uploads (PNG, JPEG, ...) are stored as JPEG. An image can also come from a BLOB column holding a JPEG: {Q1.PHOTO}.
  • Barcodes: Code 128. A table row grows with long text; a row is never split across pages.
  • Every PDF made through pdf_api is logged (Log): who, which report, pages, time, errors. The log keeps 90 days.
